A KUKA robot cell that finds, picks and threads bolts using force feedback, built to show automated fastening is feasible for remote fusion-energy maintenance.

  • Force/torque control
  • EtherCAT
  • KUKA Sim
  • TwinCAT

Vision-Guided Robotic Arm for Battery Swapping

MSc dissertation, Newcastle University

A prototype camera-guided robotic arm that detects scale-model batteries, reads their LED charge state and sorts them, aimed at giving electric two-wheeler riders only fully charged units.

  • Python
  • OpenCV
  • MyCobot 280
  • Creo
  • 3D printing
  • The camera detected each battery's position and charge colour (red, yellow or green) automatically. The arm used those coordinates to pick the battery and place it in the matching shelf position.
  • The prototype completed a full swap: a low-charge battery to the shelf, and a fully charged battery back to the work area.
Role, tools and skills

Summary

Charging stations for electric two-wheelers rely on manual battery handling, which is slow and error-prone. For my MSc dissertation at Newcastle University, I built a prototype in which a camera detects each battery and reads its LED charge indicator. The coordinates go to a six-degree-of-freedom robotic arm, which picks the battery and places it on a colour-coded shelf. The arm then swaps a depleted battery for a fully charged one.

My role

  • Completed the project on my own as a solo MSc dissertation.
  • Designed the workspace in Creo: a 2×3 shelf, a battery base and cube cases. I then laser-cut the shelf and 3D-printed the 26 mm cube "batteries".
  • Wrote the Python code that links camera detection to the arm's pick-and-place moves.
  • Calibrated the camera-to-robot coordinate mapping so the arm could locate batteries from the camera image.
  • Tested detection, pick-and-place accuracy and full swap cycles, and wrote up the work as my dissertation.

Tools and technologies

Python, OpenCV (HSV colour segmentation, contour detection), Raspberry Pi, Elephant Robotics MyCobot 280 Pi (6-DOF arm), 720p USB camera, Creo (CAD), 3D printing, laser cutting

Skills demonstrated

Self-Balancing, Fall-Safe Raspberry Pi Robot Dog

Freenove kit rebuilt

Over seven months I turned a kit robot dog into a sensing, self-protecting robot with on-device ML, smooth motion, self-balancing and fall safety.

  • Python
  • Edge Impulse
  • IMU sensor fusion
  • Control systems
  • Raspberry Pi
  • Self-balancing fixed: leg commands that swung ±55° about 4.5 times a second now hold steady (0.00 to 0.01° wobble), and simulated 6° tilts are corrected in about 1 second.
  • Pickup detection scored 91% on 580 one-second windows (99% idle, 83% pickup), measured on recorded sessions that likely overlap the training data.
  • Fall detection passed 13 of 13 hardware checks, and stand/sit became symmetric at 5.01 s / 5.00 s, with about 60% finer joint motion.
Role, phases, tools and skills

Summary

The stock Freenove robot dog jerked on power-up, shook instead of levelling in balance mode, and had no awareness of being handled or falling. Across four phases I trained an on-device pickup classifier, built smooth S-curve servo motion, prototyped multi-sensor obstacle detection, and replaced the balance controller while adding fall, drop and low-battery protection. Every change was tested on the real robot, and I corrected claims the measurements didn't support.

My role

  • Designed the motion-data collection process, recorded 95 labelled sessions and trained four Edge Impulse model versions.
  • Implemented S-curve servo motion and found a rounding bug that limited every joint to whole-degree steps.
  • Designed a five-component system that combines camera, ultrasonic and motion-sensor data with two on-device models.
  • Diagnosed why the stock balance mode oscillated, then designed a replacement filter and controller and integrated it into the robot's app control path.
  • Set fall and battery safety thresholds from measured sensor data instead of guesses.
  • Built hardware tests with simulated sensor faults, checking servo shutdown by reading the driver's registers back.

Project phases

  • Touch and pickup recognition: 95 ten-second sessions at 50 Hz, about 16 minutes of motion data. The final Idle/Pickup model reached 91% window accuracy and uses a three-window vote before the robot nods and lights up. Re-testing every version showed the three-class models labelled nearly everything as Patting, which supports the two-class design.
  • Smooth servo motion: stand/sit made symmetric at 5.01 s / 5.00 s, repeatable within ±0.004 s, and 39 to 62 distinct servo positions. Body wobble fell from 4.45 to 2.65 deg/s between 3 s and 9 s transitions.
  • Multi-sensor obstacle detection: detected a real obstacle at 21 cm, de-escalated when the path cleared, and ran object detection (6 classes) and motion classification (Idle/Pickup) at the same time on the Pi.
  • Self-balancing, fall safety and behaviours: the fall trigger sits 27° above the most extreme normal pose across 8 tricks, and drops are detected within 100 ms. Measured battery sag of 0.39 to 0.47 V per trick led to a 15-second smoothing window that prevents false low-battery alarms.

Tools and technologies

  • Hardware: Raspberry Pi, MPU6050 IMU, PCA9685 servo driver, ADS7830 ADC, ultrasonic sensor, camera, RGB LEDs
  • Software: Python, NumPy, Flask, gpiozero, smbus, picamera2, multithreading, Git
  • ML: Edge Impulse (edge_impulse_linux SDK)

Skills demonstrated

  • Embedded ML and sensor fusion
  • Control systems and motion design
  • Hardware testing and measurement
  • Root-cause debugging
  • Concurrent real-time Python

Rail Fault Detection on a Model Train

Work project, built with Literal Labs ModelMill

A compact logic-based model on a Raspberry Pi 5 model train detects staged track obstructions from vibration, at a fraction of conventional compute cost.

  • C/C++
  • Python
  • Logic-based networks
  • XGBoost
  • Raspberry Pi 5
  • On twelve recordings made after training, the logic-based model scored 0.691 balanced accuracy, ahead of XGBoost (0.670) and random forest (0.548). It uses 0.10 mJ, 54 KB of flash and 0.080 ms per inference, which is 212× faster and 220× more energy-efficient than the random forest.
  • The dataset was 36 recordings (38 minutes), turned into 2,792 windows of 80 features. Adding the longer 12.8-second timescale lifted accuracy by about 19 points.
  • It found obstructions reliably but missed a gradual ramp fault.
Role, tools and skills

Summary

Track inspection relies on dedicated inspection trains, so I tested whether a model small enough for a microcontroller could let ordinary trains report faults. I built a Raspberry Pi 5 model-railway testbed, collected 38 minutes of vibration data across staged faults, and deployed a logic-based network through Literal Labs' ModelMill.

My role

  • Built the Raspberry Pi 5 testbed, wired the MPU-6050 motion sensor, and designed the fault-staging and data-collection protocol.
  • Engineered an 80-feature, two-timescale pipeline, trained the model in ModelMill, and compiled the generated SDK on the Pi.
  • Built live inference on top of it and tested it on recordings made after training.

Tools and technologies

Raspberry Pi 5, MPU-6050 IMU (I²C), relay-controlled DC motor, Python, C/C++, CMake, gcc, ctypes, Literal Labs ModelMill (logic-based network), scikit-learn, XGBoost

Skills demonstrated

  • Embedded sensing and hardware integration
  • Experimental design and data collection, including drift-aware controls
  • Feature engineering for time-series sensor data
  • Honest model evaluation on unseen data, reporting negative results
  • Edge deployment of C/C++ models from Python

Gear Fault Detection: Data Collection and LBN Benchmark

Work project, built with Literal Labs ModelMill

Vibration data from a model V8 rig, on which a 51.9 KiB binary LBN model reached 0.94 accuracy at 0.073 ms per prediction.

  • Data acquisition
  • Python
  • LBN models
  • scikit-learn
  • Raspberry Pi 5
  • LBN scored 0.94 accuracy (the supplier's session-grouped result). The comparison models scored 0.974 (logistic regression, XGBoost), 0.949 (gradient boosting), 0.923 (decision tree, random forest), 0.856 (SVM), 0.831 (MLP) and 0.772 (k-NN).
  • LBN was the fastest of 11 models at 0.073 ms per prediction. That is 237× faster than a random forest (17.299 ms), with 11× less energy (2.65 vs 28.44 mJ) and a 28× smaller artefact (51.9 KiB flash vs 1,440 KiB pickle).
Role, tools and skills

Summary

Can a model small enough for a microcontroller detect a damaged gear? I built a Raspberry Pi 5 test rig on a working model V8 engine and recorded 500 Hz vibration data across four gearbox speeds, with tooth faults staged on 3D-printed gears. Literal Labs' binary LBN model reached 0.94 accuracy in 51.9 KiB of flash and was the fastest of 11 models compared.

My role

  • Built the 1,169-piece V8 test rig and mounted and wired the accelerometer to the Pi.
  • Diagnosed and fixed a sampling fault (69.3% sample loss, resolved by raising the I2C bus speed).
  • Staged faults on 3D-printed gears and collected the 64-session dataset.
  • Ran a pre-batch check that caught a loose timing chain before any fault recordings were made.

Tools and technologies

Raspberry Pi 5, MPU-6500 IMU (I2C), Mould King 10203 V8 kit, 3D printing, Python, Literal Labs ModelMill (LBN models), scikit-learn, XGBoost

Skills demonstrated

  • Sensor data acquisition and experimental design
  • Data quality control
  • Model benchmarking and validation
  • Embedded ML evaluation
  • Technical reporting
